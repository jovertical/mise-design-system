# The bakery's gaps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans, inline in the main session (the user's choice for this repo). Activate the authors-components, vitest-testing, git-workflow, documents-updates and writes-clean-code skills. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Close what bertos-bakery-ops, the first Inertia app on mise, found missing or wrong while mapping its 25 screens onto mise 1.4: four new pieces (`CheckboxGroup`, `MonthPicker`, `SiteHeader`, `TableSectionRow`), additions to eight existing components, and a sweep of API drift and catalogue errors.

**Architecture:** Every change is additive. New props default to today's behaviour, a renamed value keeps its old spelling working, and nothing an app writes today stops compiling, so the release is a minor (`feat`/`fix` commits only, never `feat!`). Each component follows `.claude/skills/authors-components/SKILL.md`: test first, then the parts, the barrel and `EXPECTED_EXPORTS`, stories on the skeleton, `pnpm build:skill` and the skill's index.

**Tech Stack:** Svelte 5, Tailwind v4, bits-ui 2, `@internationalized/date`, `@tabler/icons-svelte-runes`, Vitest + Testing Library, Storybook. No new dependency.

**Spec:** the bakery's audit, `bertos-bakery-ops/docs/superpowers/specs/2026-11-09-mise-gap-audit.md` (gaps G1, G3–G12 and its "mise bugs, API drift and docs" list), approved by the user on 2026-11-09. G2 was closed by 1.4.0. The handoff's open item 5 (DatePicker's `id` and trigger) folds into Task 5. The decisions table below is the rest of the spec.

## Global Constraints

- Component rules from the authors-components skill: header comment first (`Origin:` / `Svelte:` / `Diverged:`), exported `<Part>Props` with JSDoc, `ref = $bindable(null)`, `class` merged last through `cn`, `...rest` on the root, `data-slot` on every part, `.js` on relative imports. A new component with no React original is `Origin: mise`, its story tagged `mise`.
- Prop vocabulary from `docs/naming.md`: colour is `tone` (`critical` for red), treatment `variant`, size `sm | md | lg`, states bare adjectives.
- Colours only from semantic tokens and `src/lib/utils/tone.ts`; no `dark:` colour overrides; the neutral-wash rule stands.
- Story copy: generic operations (orders, shipments, stock, shifts), `$` money. Never the bakery's words.
- **No breaking change** (the user's rule: one consumer, no majors). Commits are `feat(<component>)` / `fix(<component>)` / `docs`; never `!` or a `BREAKING CHANGE:` footer.
- Commit only when `pnpm test` and `pnpm build:storybook` both exit 0, checked by exit code. Run `pnpm fix:spacing` then `pnpm format` first. A change the logistics example uses also passes `pnpm --filter mise-logistics-example test` and `smoke`.
- Work on branch `feat/bakery-gaps` (git worktree at `/Volumes/External/Code/mise-bakery-gaps`, so the main checkout's own branch is undisturbed). It reaches `main` by one pull request after the round gate; the user merges, then merges release-please's PR.
- Phase gates after Tasks 5, 10 and 15: phase-gates report with screenshots of the new stories in both schemes, wait for an explicit go. Push only after the round gate.

## Decisions

| # | Decision | Ruling |
| --- | --- | --- |
| B1 | CheckboxGroup | A new component in `forms/checkbox-group/`, `Origin: mise`: a `FieldSet` with a `FieldLegend`, one `Checkbox` + `Label` row per option, `FieldError`, and an empty text when there are no options. `value = $bindable<string[]>([])`, `options: { value: string; label: string; description?: string; disabled?: boolean }[]`, `legend`, `description?`, `errors?` (as `FieldError`), `empty?` (string, default "Nothing to choose from."), `orientation: 'vertical' \| 'horizontal'` (default vertical), `disabled`, `name` (each checkbox submits `name[]`). Values are strings; the caller maps ids |
| B2 | MonthPicker | A new component in `forms/month-picker/`, `Origin: mise`, shaped like `DatePicker`: a trigger opening a popover with a year header (‹ year ›) and a 3×4 grid of months. `value?: CalendarDate` (always day 1; a picked month emits the 1st), `onValueChange`, `minValue` / `maxValue` (months outside are disabled), `locale`, `placeholder` ("Pick a month"), `formatLabel?: (value: CalendarDate) => string` (default `MMMM yyyy` in `locale`), `disabled`, `aria-invalid`, `id` on the trigger. Month names from `Intl.DateTimeFormat(locale, { month: 'short' })` |
| B3 | SiteHeader | A new component in `layout/site-header/`, `Origin: mise`, from the client portal's site header and the logistics example's `app-header.svelte` (which then uses it): the floating bar on a blurred band, sticky, its card capped at `max-w-content` and padded like `PageLayout`. Parts: `SiteHeader` (the band and the card; `children`), `SiteHeaderSeparator` (the short vertical divider). Apps put `SidebarTrigger`, a breadcrumb, `CommandTrigger` and menus inside. `contentClass` passes the card's width cap through when an app's column differs |
| B4 | TableSectionRow | A new part of the table family, `table-section-row.svelte`: a full-width group heading row inside `TableBody` (a `tr` with one `th scope="colgroup"` spanning `colspan`, default all columns read from the table's context, `bg-muted/50 text-xs font-semibold uppercase text-muted-foreground`). `Origin: mise` |
| B5 | TimePicker | `id` and `aria-invalid` go on the hour select's trigger, not the wrapper, so `FieldLabel for` and the invalid border work (the rest still spreads on the wrapper). `hourCycle: 12 \| 24` (default 12, today's behaviour; 24 drops the AM/PM select and lists 00–23). `minuteStep` (default 1; 5, 10, 15, 30 list only those minutes, and a value off the step keeps its own minute as an extra item so nothing is lost) |
| B6 | DatePicker | `formatLabel?: (value: DateValue) => string` for single mode and `(value: DateRange) => string` for range, defaulting to today's label. `id` and the rest of the trigger's attributes reach the trigger (handoff item 5). The trigger is drawn filled like `Input` (`bg-input/50`, no outline), matching the inputs beside it |
| B7 | Readiness | `ReadinessItem` gains `severity?: 'block' \| 'warn'`, read only when `optional` is absent: `block` is required and drawn `critical` when unmet, `warn` is drawn `warning` with the label "Check" instead of "Optional". `optional: true` keeps meaning what it means. `ReadinessChecklist` gains `showDetail: 'unmet' \| 'all'` (default `unmet`, today's): `all` shows each row's `detail` on met rows too, for a record of a past check. `summariseReadiness` counts `severity: 'block'` as required and `warn` as optional |
| B8 | Button `loading` | `loading?: boolean`: draws a `Spinner` before the label, sets `aria-busy`, and disables the button (a link drops its `href`, as `disabled` does). `StepperNavigation`'s `nextLoading` passes through to it |
| B9 | NumberInput `size` | `size?: 'sm' \| 'md' \| 'lg'` (default `md`) on `NumberInput` and `NumberInputField`, matching `Input`'s heights; with `controls`, the − and + buttons scale with it. `Input` gets the same `size` if it lacks one, so a row of inputs can be dense together |
| B10 | Combobox free text | `allowCustomValue?: boolean` on `Combobox` (single only): the input's text is the value as it is typed, and an item, when chosen, sets the text to its label. `onValueChange` reports the text. Items stay suggestions; `ComboboxItem` keeps its `description` slot for the category beside each suggestion |
| B11 | Theme context | `ThemeProvider` keys its context with `Symbol.for('mise-theme')`, as the sidebar does, so two loaded copies of mise (a dev server across a version bump, a linked package) share it |
| B12 | Alert `tone` | `Alert` gains `tone?: Tone`, the vocabulary every other component uses; `variant="destructive"` keeps working and maps to `tone="critical"`, `info` / `success` / `warning` to their tones, `default` to none. The docs and stories write `tone`. `DropdownMenuItem`'s `variant="destructive"` gains the same `tone="critical"` spelling |
| B13 | Size names | Where a size prop says `default`, `md` is accepted as its name too and becomes what the docs and stories write: `AlertDialogContent`, `Toggle`, `ToggleGroup`, `SidebarMenuButton`. `default` keeps working. `InputGroupButton`'s `xs` / `icon-*` are left: they are an icon-button scale, not the `sm \| md \| lg` axis |
| B14 | `mise-theme info` | `stylesheet` also matches a CSS file whose `@source` names `@jovertical/mise-design-system/dist`, which every setup has, so an app on a generated theme is found. The generated theme's header says "Regenerate with `mise-theme <config> -o <file>`" (or `pnpm build:theme` only inside mise itself) |
| B15 | Separator | A vertical separator's height yields to a caller's `h-*` (`self-stretch` instead of a forced full height), so `<Separator orientation="vertical" class="h-4" />` is short, as the example's header writes it |
| B16 | PageHeader | The page-kind rule (list: nothing above the title; create / edit: `backLink`; detail: `breadcrumb`) moves from the source comment into the Props JSDoc, so the catalogue carries it. A `PageHeaderBackLink` part draws the back link (a ghost `Button`, small, with `IconChevronLeft` and the label; `href` and the rest of `Button`'s props), so apps stop inventing one |

## Phases

- **Phase 1, forms (Tasks 1–5):** CheckboxGroup, TimePicker, NumberInput and Input `size`, Button `loading`, DatePicker
- **Phase 2, new pieces and data (Tasks 6–10):** MonthPicker, Combobox free text, Readiness severity, TableSectionRow, SiteHeader
- **Phase 3, drift and docs (Tasks 11–15):** theme context and Alert `tone`, size names, `mise-theme info` and the theme header, Separator and PageHeader, the catalogue and setup sweep and the round gate

## Per-task specifics

Each task: read the sibling components and `docs/naming.md` first; write the failing test; implement; barrel and `EXPECTED_EXPORTS` for new exports; stories; `pnpm build:skill`; the skill's index for a new component; `Diverged:` line for every change to a ported module. Tests cover at least what is listed.

- **1 CheckboxGroup** (`forms/checkbox-group`, B1): test that ticking adds the option's value to the bound array and unticking removes it, order following `options`; a disabled option cannot be ticked; `name` gives each checkbox `name[]`; `errors` renders `FieldError` and sets `data-invalid` on the set; no options renders the empty text; each label points at its checkbox. Stories: Playground; Orientations; States (disabled, invalid, with a disabled option); With description (options with descriptions); Long content (twenty locations); In a form (a `Card` with other fields). Skill index: under Forms, "Several choices from a list: `CheckboxGroup`".
- **2 TimePicker** (B5): test that `id` lands on the hour trigger and `FieldLabel for` focuses it; `aria-invalid` on that trigger; `hourCycle={24}` lists 00–23 with no period select and round-trips `Time(17, 30)`; `minuteStep={15}` lists 00, 15, 30, 45, and a value at :07 keeps 07 listed. Stories: add Formats (12 / 24 hour), States (invalid), and In a field (with `Field` and `FieldLabel`).
- **3 Size** (B9): test `NumberInput size="sm"` and `"lg"` heights against `Input`'s at the same size, and the controls scaling. Stories: Sizes on both.
- **4 Button `loading`** (B8): test `aria-busy`, the spinner, the button disabled, a loading link without `href`; `StepperNavigation nextLoading` reaching its button. Stories: States gains Loading.
- **5 DatePicker** (B6): test `formatLabel` in both modes, `id` on the trigger with `FieldLabel for`, the trigger's filled classes. Stories: With a custom label, In a field. Remove handoff item 5's DatePicker bullets. Phase 1 gate.
- **6 MonthPicker** (`forms/month-picker`, B2): test the label from `formatLabel` and its default, picking a month emitting day 1, year navigation, months outside `minValue` / `maxValue` disabled and the year buttons disabled at the ends, `id` and `aria-invalid` on the trigger, keyboard (arrow keys move across the grid, Enter picks). Stories: Playground; States; With bounds; In a toolbar (beside a `Select`, the filter row a report screen has). Skill index under Forms: "A month: `MonthPicker`".
- **7 Combobox free text** (B10): test that typing reports the text with no item chosen, choosing an item sets the text to its label, clearing reports `''`, and without `allowCustomValue` today's behaviour holds. Stories: a `Free text` scenario (a description field with suggestions and their category).
- **8 Readiness** (B7): test `summariseReadiness` with `severity` (block counted required, warn not), the unmet `block` row drawn critical, the `warn` row's "Check" label and warning tone, `showDetail="all"` showing detail on a met row. Stories: States gains Severities; a `A past check` scenario with `showDetail="all"`.
- **9 TableSectionRow** (B4): test the `th` with `scope="colgroup"` and the column count from context, and `colspan` overriding it. Stories: a `With sections` story (a ledger-like grouped table: assets, income, expenses, with figures). Skill index: under Data display, beside `Table`.
- **10 SiteHeader** (`layout/site-header`, B3): test the band's sticky classes, `contentClass` reaching the card, `SiteHeaderSeparator` being short and vertical. Stories: Playground (trigger, separator, a breadcrumb, `CommandTrigger`, `ThemeToggle`); In a shell (with `Sidebar` and `SidebarInset`). Then the logistics example's `app-header.svelte` uses it (`chore(example)`), example gate and smoke. Skill index under Layout: "The bar above every page: `SiteHeader`". Phase 2 gate.
- **11 Theme context and Alert `tone`** (B11, B12): test that a `useTheme` resolves against a provider whose context was set by another module instance (set the context under `Symbol.for('mise-theme')` in the test and read it through `useTheme`); test `Alert tone` for each tone and `variant="destructive"` still drawing critical; `DropdownMenuItem tone="critical"`. Stories and recipes write `tone`. Remove the handoff's open item 3.
- **12 Size names** (B13): test `md` and `default` drawing the same classes on each of the four. Stories write `md`.
- **13 `mise-theme info` and the theme header** (B14): test `findStylesheet` finding a file with only the `@source` line, and still skipping `node_modules`; test the emitted header's text. Regenerate `src/lib/styles/theme.css` if its header changes.
- **14 Separator and PageHeader** (B15, B16): test a vertical separator with `class="h-4"` keeping `h-4`; `PageHeaderBackLink` rendering a link with the chevron and its label. Stories: Separator's In a toolbar; PageHeader's create and edit story uses `PageHeaderBackLink`. The logistics example's header and edit pages use `SiteHeaderSeparator` and `PageHeaderBackLink` (`chore(example)`).
- **15 The sweep and the round gate:**
  - JSDoc and generator fixes so the catalogue reads right: `TableBody` / `TableFooter` (`<tbody>`, `<tfoot>` attributes), `FactList` (`<dl>`), `Select` / `Combobox` (no doubled "Also takes", `type` showing both values, `items` in `Select`'s table), `Input`'s `type` optional, `FormLegend`'s stray prefix, descriptions for `Checkbox`, `Label`, `Switch`, `RadioGroup`, `StepDefinition.description` documented, `TimePicker`'s `Time` value and hour cycles, `FactListItem.valueClass` described as layout only.
  - `Checkbox`'s `dark:` colour overrides replaced by tokens.
  - Sonner's header no longer says mise has no theme provider.
  - `NumberInput`'s `min` description says the default floor is 0 and a signed amount sets its own.
  - `skills/mise/setup.md` lists, for pnpm apps, the mise dependencies an app adds to import them itself: `@tabler/icons-svelte-runes` (icons, `EmptyState`), `@internationalized/date` (date and time values), `layerchart` and `d3-scale` (charts).
  - Round gate: clean-tree gate, both example checks, every new or changed story in both schemes, `docs/handoff.md` (what shipped, the bakery follow-up), push the branch, open the pull request, watch CI, hand over.
