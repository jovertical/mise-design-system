# The logistics example: a hosted showcase built only from mise

Date: 2026-11-09. Status: approved in conversation, awaiting the written review.

## Problem

mise is on npm, with Storybook as its only demonstration, and Storybook is not hosted. Someone
deciding whether to use mise cannot see what an application built from it looks like: a shell,
a dashboard, tables, a detail page, forms and overlays working together on believable data. Nor
is there anything in the repository that uses mise the way an app does, through the package's
exports, its stylesheet and a generated theme, so a packaging or composition gap shows up only
when an outside app hits it.

## Goal

A logistics operations app in `examples/logistics/`, hosted on GitHub Pages, that:

1. is built only from mise components, with no forks and nothing re-implemented locally;
2. looks finished in light and dark, under its own generated theme;
3. runs on mock data that a visitor can change (create an order, cancel it, edit a product),
   persisted in the browser and resettable;
4. builds against mise's `main` on every push, so a change that breaks it fails CI.

## Reference

The screen inventory and the kinds of data are taken from a public logistics dashboard template
(shadcn/studio's "Cargorix", captured with a headless browser on 2026-11-09). It is a paid
template: only which screens a logistics app has and what they show is taken from it. No code,
copy, names, layout specifics or assets are copied. The captures stay outside the repository.

## Decisions

| # | Decision | Ruling |
| --- | --- | --- |
| E1 | Purpose | A public showcase. Polish matters more than breadth |
| E2 | Stack | SvelteKit with `@sveltejs/adapter-static`, client-rendered (`ssr = false`), deployed to GitHub Pages |
| E3 | Scope | The core 8 screens below. The other screens of the reference are out of scope |
| E4 | mise source | The pnpm workspace: `"@jovertical/mise-design-system": "workspace:*"`, built from the repository's `main` |
| E5 | Mock data | A fixed, hand-written seed behind a runes store persisted to `localStorage`, with a reset |
| E6 | Gaps | Anything the screens need that mise lacks is added to mise first, under its own plan, before the screen that needs it. Nothing is built locally in the example |
| E7 | Theme | The example's own theme, generated with `mise-theme` from `mise.theme.js` (theming level 3) |
| E8 | Architecture | A single-page app with a client-side store (approach A); not prerendered |

## Workspace, build and hosting

```
examples/logistics/
  package.json          name "mise-logistics-example", private, "workspace:*" on mise
  vite.config.ts        sveltekit({ adapter: adapter-static({ fallback: '404.html' }),
                                     paths: { base: process.env.BASE_PATH ?? '' } }),
                        @tailwindcss/vite
  mise.theme.js         the brand
  src/app.css           tailwindcss, tw-animate-css, ./mise-theme.css, @source on mise's dist
  src/mise-theme.css    generated by `pnpm theme`, committed
  src/routes/           the shell and the screens
  src/lib/data/         the seed, the store, the repositories, the schemas
  src/lib/components/   compositions for this app only: a vehicle card, an order sheet
  scripts/smoke.ts      the route smoke test
```

- `pnpm-workspace.yaml` gains `packages: ['examples/*']`. mise's `files` ships only `dist`,
  `bin`, `skills` and `LICENSES`, so the example never enters the tarball.
- The example consumes mise as an app does: through the package's `exports`, `theme.css`'s
  replacement generated by `mise-theme`, and a Tailwind `@source` on
  `node_modules/@jovertical/mise-design-system/dist`. The workspace link is a symlink to the
  repository root, so "compiling" mise for the example is mise's own `pnpm build`; there is no
  copy into `node_modules`, and Vite does not pre-bundle a linked package, so a rebuilt `dist/`
  is picked up without `--force`.
- A root script, `pnpm dev:example`, runs `svelte-package --watch` and the theme build beside
  the example's dev server, so a change in `src/lib` reaches the example on save.
- `src/lib/components/` in the example holds compositions of mise parts specific to this app
  (a vehicle card for the fleet grid, the create-order sheet). It never holds a component mise
  should have (E6).
- `.github/workflows/example.yml`, on push to `main` touching `src/`, `skills/` or `examples/`:
  install, build mise, build the example with `BASE_PATH=/mise-design-system`, upload with
  `actions/upload-pages-artifact`, deploy with `actions/deploy-pages`. Hosted at
  `https://jovertical.github.io/mise-design-system/`. The user enables Pages with GitHub Actions
  as the source before the first deploy.
- A deep link (`/orders/OR-2041`) is served by `404.html`, which boots the app and routes it. The
  HTTP status of that first response is 404, which no visitor sees and which does not matter for
  a demo.
- Example commits are `docs(example)` or `chore(example)`, so they never move mise's version.

## The shell

`src/routes/+layout.svelte`, for the fictional company "mise Logistics (demo)":

- `ThemeProvider` (`storageKey="mise-logistics-demo-theme"`), `Toaster`, `NavigationProgress`.
- `SidebarProvider` and `Sidebar`, grouped: Overview; Orders (Orders, Shipments); Fleet;
  Inventory (Products, Warehouses); Partners (Clients); Settings (General).
- A header with `Breadcrumb`, a ⌘K `CommandDialog` searching orders, clients and products, and
  `ThemeToggle`.
- A user `DropdownMenu` with **Reset demo data**, confirmed through an `AlertDialog`.

## The screens

Each screen is `PageLayout` with `PageHeader`. Copy is generic operations; locations are
invented (Riverside DC, Harbour Hub, North Yard, Market Street); money is `$`.

| Route | Purpose | Built from |
| --- | --- | --- |
| `/` | Operations overview: the day at a glance | `StatTile` ×4 with `DeltaBadge` and `Sparkline`; fleet status as `SegmentedBar` and `FactList`; the fulfilment pipeline as `Tabs` over `MetricBar`s; deliveries as an area chart in `ChartContainer`; fleet condition as `RadialStat`s; active shipments as a `DataTable` with a "View all" footer |
| `/orders` | Incoming orders | `StatTile` row; `DataTable` with search, a status filter, a source `Badge`, the client as `EntityLabel` with `Avatar`, row actions; a Table / Board toggle; **Create order** in a `Sheet` (`Combobox` client, `Select` service, `QuantityInput` weight, `NumberInput` currency) that saves and confirms with a `toast` |
| `/orders/[id]` | One order | `Breadcrumb`; a status `Badge` in `titleAccessory`; a `FactList` card; a `Timeline` of status events; a packages `Table`; an `AsideCard` for its shipment; **Cancel order** through `AlertDialog` |
| `/shipments` | Shipments in motion | `DataTable`; a row opens a `Sheet` with a `Timeline` of stops and a `Progress` |
| `/fleet` | Vehicles | `DataTable` with the table / grid `viewMode`, a vehicle card in grid view, status `Badge`s, a service-due `Alert` |
| `/products` | Stock | `DataTable`; on hand, reserved and available as a `SegmentedBar`; a low-stock `Alert`; an edit `Dialog` form |
| `/warehouses` | Sites | `CardGrid` of warehouse cards: a utilisation `RadialStat`, docks in a `FactList`, a `MetricBar` per zone |
| `/clients` | Customers | `DataTable` with `EntityLabel`; client detail in a `Sheet` with a `FactList` and a recent-orders `Table`; an add-client `Dialog` |
| `/settings/general` | Company settings | `mise/form` with superforms in SPA mode: `Input`, a timezone `Select`, a units `ToggleGroup`, `SwitchField`s; saving confirms with a `toast` |

Every list screen has its loading state (the data layer's latency makes it show), its empty
state for a filter that matches nothing, and an error state reached through an unknown id
(`/orders/does-not-exist` renders `ErrorState`).

### Gaps known before the work starts

1. **Board.** The Orders "Board" view is columns of cards grouped by status, read-only. mise has
   no such component. It is added to mise first (working name `Board`, with `BoardColumn` and
   `BoardCard`), under its own plan, tests and stories. Dragging between columns is not part of
   it; that stays with the deferred drag-and-drop components.
2. **Map.** Not built. Live Map is outside the core 8, and a map library is too heavy a
   dependency for mise.

Any further gap found while building a screen stops that screen until mise has it (E6).

## Data and state

### The seed

`src/lib/data/seed/`, typed, hand-written and fixed, so the demo and its screenshots are stable:

| Entity | Count | Fields |
| --- | --- | --- |
| `Location` | 4 | id, name, city, manager, capacity, docks, utilisation per zone |
| `Vehicle` | 12 | id, code, registration, type (`van`, `truck`), home location, status, mileage, next service |
| `Driver` | 10 | id, name, phone, vehicle, licence expiry, availability |
| `Client` | 14 | id, name, industry, contact, city, account manager, lifetime value (cents) |
| `Product` | 24 | id, SKU, name, category, unit, price (cents), stock per location (on hand, reserved) |
| `Order` | 60 | id, number, client, source (`api`, `portal`, `csv`, `manual`), service, packages, weight, total (cents), status, events |
| `Shipment` | 18 | id, number, vehicle, driver, origin, stops, ETA, status, progress |

Dates are offsets from a fixed `DEMO_TODAY`, so the demo never looks stale. Money is integer
cents; ids are strings.

### The store

`src/lib/data/store.svelte.ts`: one `$state` object holding every collection. On load it reads
`localStorage['mise-logistics-demo:v1']`, or deep-copies the seed. A debounced `$effect` writes
it back. `reset()` restores the seed. The key's version is bumped whenever the seed's shape
changes, which discards an older saved store instead of reading it wrongly.

### Repositories

`src/lib/data/<entity>.ts`: plain functions over the store, the only way pages read or change
data.

- Reads: `listOrders(filters)`, `getOrder(id)`, `orderStats()`, `pipeline()`, `fleetStatus()`,
  `fleetCondition()`, `deliveryTrend()`, `listProducts(filters)`, `warehouseUtilisation(id)`,
  and the like.
- Writes: `createOrder(input)`, `cancelOrder(id)`, `updateProduct(id, patch)`,
  `createClient(input)`, `saveSettings(settings)`.
- Every derived figure (stats, pipeline counts, utilisation, condition buckets) is a pure
  function of the store, unit-tested against the seed.
- Pages await `latency()` (about 250 ms) before a read resolves, so loading states are real.
  Tests turn it off.

### Validation

zod schemas in `src/lib/data/schemas.ts`, shared by the forms (superforms, SPA mode) and the
write functions, which reject input the schema rejects.

## Theme

`examples/logistics/mise.theme.js`:

```js
import { defineTheme } from '@jovertical/mise-design-system/tokens'

export default defineTheme({
  base: 'stone',
  primary: 'teal',
  status: { warning: 'amber' },
  charts: ['teal', 'sky', 'amber', 'rose', 'violet'],
  radius: '0.5rem',
})
```

`pnpm theme` runs `mise-theme mise.theme.js -o src/mise-theme.css`. The output is committed; a
test regenerates it and fails when it differs. Dark mode is the `ThemeProvider` above.

## Checks

`pnpm --filter mise-logistics-example test`, which the root `pnpm test` also runs:

1. `svelte-check` and Biome over the example.
2. Vitest: the repositories and derived figures against the seed; `createOrder` and
   `cancelOrder`; `reset`; a stored blob with an old version key being discarded; the theme
   file being current.

`pnpm --filter mise-logistics-example smoke`, run locally before each phase report (CI has no
browser without a new dependency): after `vite build`, `scripts/smoke.ts` serves `build/` and
opens every route, including an order deep link and an unknown id, in light and dark with the
headless Chromium already on the machine. It fails on a console error, an uncaught exception or
an empty `<main>`, and writes a screenshot per route and scheme.

## Dependencies

The example's own, installed by the user when the plan reaches them: `@sveltejs/kit`,
`@sveltejs/adapter-static`, `@sveltejs/vite-plugin-svelte`, `vite`, `svelte`, `tailwindcss`,
`@tailwindcss/vite`, `tw-animate-css`, `formsnap`, `sveltekit-superforms`, `zod`, `layerchart`,
`d3-scale`, `d3-shape`, `@tanstack/svelte-table`, `@lucide/svelte`, `vitest`, `typescript`,
`svelte-check`. Most are already in the repository's lockfile through mise.

## Order of work

1. The workspace, an empty shell, the theme, and the Pages deploy, live.
2. The data layer: seed, store, repositories, schemas, tests.
3. `Board` in mise, under its own plan.
4. The screens, about two per phase.
5. Polish (loading, empty and error states, ⌘K, reset), the smoke run, and the README and npm
   links to the demo.

## Out of scope

- A map, Live Map, and the other screens of the reference.
- Authentication, roles and a backend.
- Dragging cards between board columns.
- End-to-end tests in CI.
- A custom domain.
